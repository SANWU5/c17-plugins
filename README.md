# C17 扩展插件

Status C17 的公开插件规范、SDK 开发模板与分发目录。协议支持 **API 1/2**；API 1 用于 Status C17 2.0 起的隔离式设置和规则，API 2 为完整 Java/Android 运行扩展，需要 API 2 宿主。2.0.1 / code193 使用「扩展插件」名称并增加公开仓库目录接入。主应用源码和 APK 不在本仓库。

**当前公开目录为空，不提供可直接安装的示例插件。** [`index.json`](index.json) 的 `plugins` 为 `[]`。`templates/` 只供开发者阅读、复制和改写，不列入应用中的插件下载列表，也不代表任何 ROM 已通过适配。

**所有新插件和升级包都必须提供完整设置。** 在 `ui` 逐项展示与功能实际关联的可调参数、默认值、范围及恢复方式，至少包含一个开关、滑块、输入框或选择项；空表单、只有说明/按钮或无关占位配置不予收录。code196 起宿主对真实输出强制检查基础配置要求；标准打包工具同时检查严格 JSON 表单声明，参数是否覆盖全部功能仍需人工审阅。详见[分发规范](SPEC.md#能力与适配)。

## 当前可以做什么

插件由单个 `.js` 或带 `plugin.json` 的 ZIP 导入，并声明自己的原生设置表单。API 1 提供隔离运行和宿主有限规则：

- `settings`：临时覆盖 C17 已有、可见且经过类型与范围检查的设置，不改写用户保存的主配置。
- `systemui`：对核验过的明确 SystemUI 类/方法应用文字字面修正、View 属性或基本类型返回值规则。原方法先执行，规则随后应用。

API 2 声明 `runtime` 能力并提供 ZIP 内运行入口或内联 `runtime.source`。启用后完整代码直接运行在 SystemUI 进程中，可调用该进程可用的 Java/Android API、反射、Hook、DEX、文件、线程和对象；运行入口不受 API 1 的能力白名单、Hook 数量、脚本预算或资源包配额限制。导入时元数据编译仍隔离并有预算，表单总项数不受 API 1 的 64 项限制。API 2 安装默认停用，启用表示信任插件代码。安全模式可以撤销普通受管 Hook；显式保留的原生保护 Hook 需由插件恢复并保持兼容保护至 SystemUI 重启，详见 SDK。宿主无法恢复代码自行改变的系统数据或进程状态，也无法保证无限循环、内存耗尽等行为不会令 SystemUI 崩溃。它不会自动获得 Root。

**`action/status` 表单及 `C17.onAction/publishStatus` 最低需要 Status C17 2.1.0_beta.008 / code206。** code205 虽支持 API 2，仍不接受这两种新表单控件；`apiVersion:2` 本身不保证全部后续接口可用。发行说明必须写清最低宿主，旧 `button` 仍是持久赋值控件。动作每次点击绑定当前运行实例，不会因重载重放；安全模式仍暂停运行。接口与声明、调用示例见 [SDK](docs/SDK.zh-CN.md#一次性动作与只读状态)。

导入须先查看能力并确认安装，安装和升级都默认停用。启用后的设置或规则冲突会被拒绝；停用、移除及安全模式可撤销插件覆盖。实际效果依赖宿主版本、模块激活和目标 ROM；导入成功不等于适配成功。

code202 起，控制中心自由编辑业务由独立 API 2 插件实现，宿主不再执行旧 `qs_card_*` 布局输出；原键仍用于旧库读取和升级兼容。插件应提供顶部区域、手动音乐尺寸与「更多磁贴」独立页面的完整设置和回退约定。当前公开目录仍为空，不分发本地审阅插件包或安装示例。

在线目录的身份、版本和能力声明必须与实际包一致。目录漏写 capabilities 按空数组处理；包有能力而目录漏报时，客户端会拒绝导入，哈希校验通过也不会绕过这项检查，详见 [分发规范](SPEC.md)。

## 开发与本地打包

构建器使用 Python 3.10+ 标准库；完整的 JSON Schema 测试还需要安装 `jsonschema`，缺少它时该组测试会标记跳过。先复制 `templates/<模板>/` 到自己的开发目录，修改 ID、名称、作者、许可和行为，核验目标 ROM，再构建并导入本地测试：

```powershell
python tools/pack.py lint templates/clock-seconds
python tools/pack.py build-all --out dist
python -m unittest discover -s tests -v
```

`build/build-all` 只生成本地开发包和校验和，**不会更新公开目录**。明确准备发布实际插件时，阅读 [发布说明](docs/PUBLISHING.zh-CN.md)，使用单独的 `publish` 命令生成本地 `packages/` 与 `index.json`，经过审查再提交。工具拒绝直接把本仓库教学模板发布到目录。

ZIP 文件按名称排序，使用固定时间与权限，便于重建。`pack.py` 检查标准源码头和包结构，不执行 JavaScript；应用仍会执行真实语义校验。SHA-256 只验证下载内容一致，**不是安全认证、作者签名或代码审查结论**。
